# B482 — Registered Android Notification Sensor

## Goal

Move Android notifications out of the legacy notification-specific Photon path and into the same
productive sensor contract already used by hardware sensing:

```text
NotificationListenerService
        |
        v
LiveNotificationPhotonIngress
        |
        v
AndroidNotificationSensorBridge
        |
        +-- AppSensorRegistry
        +-- B459 SensorAttentionRuntime
        +-- B480/B481 WorldGap coverage + attention
        |
        v
CanonicalPhotonIngress.ingestSensorBatch
        |
        v
B467 structural validation
        |
        v
Owner Observation Policy
        |
        v
canonical ORIGIN Photon
        |
        v
Continuous Cognition
```

## What changed

- `ProductivePerceptionContextRuntime` now supports multiple
  `ProductiveSensorAttentionTarget` instances behind one AppSensorRegistry and one B459 scheduler.
- `AndroidHardwareSensorBridge` implements the shared target contract.
- `AndroidNotificationSensorBridge` is a registered EVENT_DRIVEN notification sensor with its own
  deterministic process cursor and one-observation B467 batches.
- Notification attention is fail-closed at `SUSPENDED`: events are ignored and the cursor does not
  advance.
- FOCUSED/PERIODIC/EVENT_DRIVEN remain event-driven at the Android platform layer; their productive
  salience differs, but LIFEOS does not invent polling for NotificationListenerService.
- Notification coverage is bounded to `app.notification.*` and `app.communication.*` plus explicit
  notification/communication readback contracts.
- The old direct `CanonicalPhotonIngress` notification authorization/fusion path is removed, so
  notifications no longer bypass the registered sensor registry/attention path.

## Authority invariants

- Android notification-listener access != Owner Observation Policy authority.
- Sensor registration != Owner Observation Policy authority.
- Sensor attention != observation grant.
- A notification observation still crosses B467 Owner Observation Policy before Photon persistence.
- Notification action handles remain separate from descriptive notification observation.
- Observation authority != Owner Effect Policy authority.
- No notification event can create effect authority or execute another app merely by being observed.
- B467 remains the only productive observation -> ORIGIN Photon -> Continuous Cognition boundary.

## Recovery / identity

The notification bridge advances its process cursor only after the canonical B467 batch call
returns. The observation itself retains the source revision generated by
`LiveNotificationListenerService`; durable Photon/cognition idempotency remains owned by the
canonical ingress and durable runtime layers.

## Next

The next block should bring app-usage and semantic app-surface observation under the same
multi-sensor target model, then project explicit app state dimensions so B480/B481 WorldGap demand
can focus only the relevant apps/surfaces.
